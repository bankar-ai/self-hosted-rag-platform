# ERP-113 — Fix missing RATE_LIMIT_REDIS_URL on the live VM

Status: Done
Depends On: None
Category: Bug

## Description

Live trace investigation (2026-09-28, a real `/generation/query/stream` request) found every
request on the live VM hits a `redis.exceptions.ConnectionError` trying to reach rate-limiting
Redis at `localhost:6379` (fails open per `app/core/rate_limit.py`'s documented design, so
requests still succeed — but the actual rate limit, ERP-108, has never been enforced in
production since it shipped). Root cause confirmed via `grep`: `RATE_LIMIT_REDIS_URL` was never
added to `~/app/.env`, so `RateLimitSettings` falls back to its default
(`redis://localhost:6379/0`), which doesn't exist on this VM — only Upstash (remote) does. The
other three Redis-backed settings (`EMBEDDING_REDIS_URL`, `RETRIEVAL_REDIS_URL`,
`AUTH_REDIS_URL`) already correctly point at the shared Upstash instance; `RATE_LIMIT_REDIS_URL`
was simply missed when `ERP-108` was deployed.

## Acceptance Criteria

- [x] `RATE_LIMIT_REDIS_URL` added to `~/app/.env`, same Upstash connection string already used
      by the other three Redis-backed settings
- [x] Service restarted (`restart_app.bat` — config-only, no code pull needed)
- [x] Live-verified: a real request no longer logs the `ConnectionRefusedError` traceback —
      confirmed via `journalctl` immediately before and after the fix, same request shape,
      error present before / absent after

## Progress (2026-09-28) — closed out

Config-only fix, no code/PR. Added the missing env var directly to `~/app/.env` via SSH
(`printf ... | sudo tee -a`), restarted via the same command pattern `restart_app.bat` wraps.
Live-verified with a real `/generation/query` call: previously every request logged a full
`redis.exceptions.ConnectionError` traceback trying to reach `localhost:6379`; the same request
shape afterward logged cleanly with zero rate-limit errors. Throwaway verification user deleted
via the `ERP-040` admin endpoint.

# ERP-071 — Bulk Document Delete + Delete Confirmation

Status: Done
Depends On: None
Category: Improvement

## Description

No way to select and delete multiple documents at once, and no confirmation before any delete
(single or bulk) — a destructive action with no safety check. See
`docs/superpowers/specs/2026-09-19-post-erp050-live-feedback-design.md` for the full design.

## Acceptance Criteria

- [ ] Each document row gets a checkbox; a "select all" checkbox above the list
- [ ] A "Delete selected (N)" button appears once one or more documents are checked
- [ ] Both single delete and bulk delete show a `window.confirm` naming exactly what will be
      deleted before proceeding
- [ ] Bulk delete reuses the existing `DELETE /documents/{id}` endpoint via `Promise.all` (no
      new bulk-delete backend endpoint)
- [ ] New tests cover: confirmation gates the delete (declining does nothing); bulk delete calls
      the endpoint once per selected document

## Notes

None.

## Resolution (2026-09-19)

Checkbox per document row + "select all" + a "Delete selected (N)" button, reusing the existing
`DELETE /documents/{id}` endpoint via `Promise.all` (no new backend endpoint). A native
`window.confirm` naming the exact file(s) gates every delete, single or bulk. A final
whole-branch review caught two real bugs before merge, both fixed in the same pass: (1)
`deleteDocuments` removed rows from the UI even when the underlying delete failed (a 403/500
looked like success until a reload); (2) a network-level rejection on one delete could leave
every attempted row stuck disabled on "Deleting..." forever, since the cleanup code never ran.
Both fixed (per-ID success tracking, no promise ever rejects). Merged to `develop` via PR #50.

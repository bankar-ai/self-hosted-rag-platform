# ERP-085 — Verify (and Fix if Needed) Mobile Browser Usability

Status: In Progress
Depends On: None
Category: Improvement

## Description

ERP-078 (responsive layout, 2026-09-19) added breakpoint-based behavior for narrow viewports —
the sidebar and source panel collapse into overlays below the `md` Tailwind breakpoint instead
of a fixed three-column layout — and ERP-079 (2026-09-19) added keyboard/focus-trap handling to
the source panel dialog. **Neither had ever been checked on a real phone or in an actual narrow
browser window** before this ticket. Coverage before this was automated unit tests only
(`vitest`/`jsdom`), which don't exercise real touch interaction, real viewport/zoom behavior, or
real mobile browser quirks (iOS Safari's address-bar height changes, tap-target sizing, etc.).

## Acceptance Criteria

- [x] Load the live app on a real phone and walk through: opening/closing the sidebar overlay,
      sending a chat message, opening a citation's source panel, closing it
- [x] Note any real usability problems found (broken layout, unreachable controls, text
      overflow, tap targets too small, etc.)
- [ ] Fix what's found

## Verification (2026-09-21, real Android phone, Chrome, live Vercel deployment)

Walked through the full flow on a real device against the live app. Findings:

1. **Top nav/header overflows and collides with the page title** — "Self-Hosted RAG Platform"
   wraps to 4 lines at this width and the nav row (Chat / Documents / email / hamburger Menu)
   doesn't reflow around it — it visually overlaps the wrapped title instead.
2. **Page-level horizontal scroll exists to reach nav items** — "Documents", the email, and
   "Log out" are only reachable by scrolling the whole page sideways. This directly violates
   ERP-078's own acceptance criterion ("no horizontal scroll of the page body") — the header
   was evidently never covered by that responsive pass.
3. **Source panel text overflows horizontally instead of wrapping** — chunk text (e.g. an
   invoice/GST line) gets clipped at the right edge rather than wrapping to the panel width.
4. **Source panel's Copy/Close controls are off-screen by default** — reaching them requires
   the same horizontal scroll as #3, i.e. a real tap-target reachability problem, not just
   cosmetic.
5. Sidebar overlay (New chat / recent conversations / document checklist with confidence
   badges) rendered correctly and was fully usable — no issues there.

Likely root cause pattern for #1–4: fixed-width/`nowrap` flex rows in the header and in
`SourcePanel` that were never given `flex-wrap` / `min-w-0` / `break-words` treatment — worth
checking both plus scanning for other `flex`/`inline-flex` rows with long text nearby.

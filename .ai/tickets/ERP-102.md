# ERP-102 — No "Jump to Latest Message" Control After Scrolling Up in Chat

Status: Backlog
Depends On: None
Category: Improvement

## Description

Found during live dashboard/UX review (2026-09-27). `ChatPage.tsx`'s ERP-064 auto-scroll
(`bottomRef.current?.scrollIntoView(...)`, ~line 248-250) keeps the latest message in view as
the conversation grows or streams in — but only while the user hasn't scrolled away. Once a
user scrolls up to re-read earlier messages, there is no affordance to jump back to the bottom
except manually scrolling all the way down themselves. Switching conversations/tabs does
correctly land on the latest message (expected, not a bug) — this is specifically about
returning to the bottom *within* the currently-open conversation after scrolling up.

## Acceptance Criteria

- [ ] A visible "jump to latest" control (e.g. a floating button) appears once the user has
      scrolled away from the bottom of the current conversation.
- [ ] Clicking it scrolls to the latest message (same behavior as the existing auto-scroll).
- [ ] The control does not appear when already at (or near) the bottom.
- [ ] The existing ERP-064 auto-scroll-while-streaming behavior is unchanged for a user who
      hasn't scrolled away.

## Notes

Needs a scroll-position listener on the message list container to know whether the user is
away from the bottom — check whether an existing library dependency already covers this (e.g. a
resize/intersection observer already used elsewhere) before adding a new one, per this project's
dependency policy.

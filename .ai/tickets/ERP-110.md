# ERP-110 — Select-All Checkbox Redesign and Conversation Delete

Status: Done
Depends On: ERP-101
Category: Improvement

## Description

Live feedback from a real session (2026-09-28): the ERP-101 "Select all"/"Deselect all" text
links had no visual state of their own — clicking them worked, but nothing about the control
itself reflected the current selection. Separately, conversations have no delete option at
all — rename (ERP-061) and per-message feedback (ERP-045) exist, but a conversation, once
created, can never be removed.

## Acceptance Criteria

- [x] Replace the two text-link buttons with a single checkbox reflecting the underlying
      selection: checked when everything is selected, unchecked when nothing is, indeterminate
      for a partial selection.
- [x] `DELETE /conversations/{id}`, scoped to the caller's own conversations (404 for
      unknown/other-owner, matching every other conversation endpoint's convention).
      Deleting the currently-open conversation starts a new one client-side.
- [x] Regression test coverage for the checkbox's three visual states and both the
      confirmed-delete and declined-delete paths.

## Notes

While building the delete cascade (message_feedback + production_sample_scores must be
cleared before conversation_messages, before the conversation row), found and fixed a related
latent bug: `app.auth.repository.delete_user_and_owned_data` (full account deletion) never
cleaned up `production_sample_scores` — added after ERP-097 shipped, never retrofitted there.
Fixed with the same pattern in both places.

## Resolution (2026-09-28)

`Sidebar.tsx` gained a master `<input type="checkbox">` (a ref + `useEffect` setting the
DOM-only `.indeterminate` property, since there's no JSX prop for it) replacing the old
buttons. New `delete_conversation` in `app/generation/repository.py` (cascading delete
mirroring `delete_user_and_owned_data`'s pattern), `app/generation/service.py`, and a
`DELETE /conversations/{id}` endpoint in `app/generation/router.py`. `Sidebar.tsx` gained a
per-row delete button; `ChatPage.tsx`'s `handleDelete` confirms via `window.confirm` before
calling it, and starts a new conversation if the deleted one was active.

Verified: backend full suite 606 passed, ruff/mypy clean; frontend 97 vitest tests passed (was
95), `tsc -b`/`oxlint`/`vite build` clean. New tests cover the checkbox's indeterminate state,
both delete-confirmed/declined paths, and (at the repository level) the exact FK-violation
scenario the `production_sample_scores` fix addresses. Merged to `develop` via PR #80, promoted
to `main` via PR #81 (both 2026-09-28); no schema migration in this range. Live-verified via a
full create → read → delete → confirm-gone round-trip against the production API. Session log:
`.ai/sessions/2026-09-28-select-all-redesign-conversation-delete-and-live-outage.md`.

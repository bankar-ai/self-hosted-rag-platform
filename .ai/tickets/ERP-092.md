# ERP-092 — Intro / Onboarding Page for New Users

Status: Done
Depends On: None
Category: Feature

## Description

Live feedback (2026-09-24): a first-time user lands directly in the chat interface with no
explanation of what this tool does or how to use it (upload documents, ask grounded questions,
click citations to see sources, per-document scoping, etc.). Needs a short intro/onboarding
surface.

## Decisions (given directly by the user, 2026-09-24)

- **Where**: both — a one-time modal on first login, and a permanent page linked from the
  header, sharing the same content.
- **Content**: simple language, bullet points, precise and to the point; must explicitly state
  what the tool *can't* do, not just what it can.

## Acceptance Criteria

- [x] Decision recorded on the open questions above
- [x] Intro page/modal built and wired into the app per that decision
- [x] Content is accurate to what the app actually does today (avoid overpromising features not
      built, e.g. no DOCX/PPTX ingestion — see roadmap)

## Built (2026-09-24)

- `frontend/src/lib/introContent.tsx` — shared `CAN_DO`/`CANNOT_DO` bullet-point arrays, reused
  by both surfaces below (no content duplication).
- `frontend/src/pages/AboutPage.tsx` — permanent page at `/about`, linked from `AppShell`'s nav
  as "How it works".
- `frontend/src/components/IntroModal.tsx` — one-time modal shown on first *authenticated*
  login, gated by a `localStorage` flag (`introSeen_v1`). Dismissible via "Got it" or a "Read
  the full guide" link to `/about`. A pre-review correctness bug was caught and fixed before
  merge: the plan's original placement (unconditional, inside `AuthProvider` but outside
  `Routes`) made the modal mount on `/login` too, before authentication — fixed by gating on
  `useAuth()`'s authenticated state.
- Content covers: uploading PDFs, grounded Q&A with citations, clicking citations to see
  sources, per-document scoping, saved conversation history — and explicitly what it can't do:
  PDF-only (no DOCX/PPTX), no cross-user document sharing, refuses ungrounded questions instead
  of guessing, no original-file download.
- Built via `superpowers:subagent-driven-development` (2 tasks, both task-reviewed and
  Approved). Full frontend suite (74 passed), `tsc`/`oxlint`/`vite build` clean.

## Notes

# ERP-092 — Intro / Onboarding Page for New Users

Status: Backlog
Depends On: None
Category: Feature

## Description

Live feedback (2026-09-24): a first-time user lands directly in the chat interface with no
explanation of what this tool does or how to use it (upload documents, ask grounded questions,
click citations to see sources, per-document scoping, etc.). Needs a short intro/onboarding
surface.

## Open Questions (need user decision before implementation)

- **Where does it live?** A one-time modal/overlay shown on first login (dismissible, tracked
  via `localStorage` or a user-profile flag) vs. a dedicated always-accessible route (e.g.
  `/about` or `/help` linked from the header)? These aren't mutually exclusive.
- **Content**: a short static explainer is enough for v1 (what the tool does, upload → ask →
  click citations flow) — confirm scope before writing copy, so this doesn't grow into a full
  docs site.
- **Re-showable?** Should a returning user be able to reopen it (e.g. a "?" or "How it works"
  link), or is it strictly first-run only?

## Acceptance Criteria

- [ ] Decision recorded on the open questions above
- [ ] Intro page/modal built and wired into the app per that decision
- [ ] Content is accurate to what the app actually does today (avoid overpromising features not
      built, e.g. no DOCX/PPTX ingestion — see roadmap)

## Notes

Frontend-only, no backend changes expected unless the "shown once" state needs to be
server-persisted per user rather than per-browser (`localStorage`).

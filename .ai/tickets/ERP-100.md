# ERP-100 — Copy Button Roles Are Reversed (Question vs. Answer)

Status: Backlog
Depends On: None
Category: Bug

## Description

Found during live dashboard/UX review (2026-09-27). In `ChatPage.tsx`, the copy affordance on
each message bubble does the opposite of what its label implies:

- The **user's question** bubble has a button labeled "Copy Q&A" (`ChatPage.tsx` ~line 556-566)
  that copies the question **and** the following assistant answer (`buildTurnText(message.content,
  next?.content)`).
- The **assistant's answer** bubble has a button labeled "Copy" (~line 589-593) that copies
  **only** `message.content` (the answer alone).

The user's expectation (and the more natural mapping): the question's own copy button should
copy only the question; the answer's copy button should be the one offering the full Q&A pair.

## Acceptance Criteria

- [ ] The question bubble's copy button copies only the question text.
- [ ] The answer bubble's copy button copies the question + answer pair (reusing the existing
      `buildTurnText` helper).
- [ ] Labels match behavior (e.g. answer bubble's button becomes "Copy Q&A", question bubble's
      becomes plain "Copy").
- [ ] Existing `ChatPage.test.tsx`/`CopyButton.test.tsx` coverage updated to match the corrected
      behavior, not just re-pointed at the same assertions.

## Notes

Purely a same-file swap of which `CopyButton` gets which `getText`/`label` props — no new
component or API needed.

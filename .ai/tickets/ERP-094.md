# ERP-094 — Cap on Number of Documents per Multi-File Upload

Status: Backlog
Depends On: None
Category: Improvement

## Description

Live feedback (2026-09-24): `DocumentsPage.tsx`'s upload control (`multiple` file input,
`DocumentsPage.tsx:298`) currently has no limit on how many files can be selected/queued in one
multi-file upload — only a per-file size label ("Maximum file size: 20 MB per PDF"). An
unbounded batch could overwhelm the ingestion pipeline (each file becomes its own job; a large
batch could also stack up multiple docling Cloud Run cold-starts/OOM-risk documents at once,
compounding ERP-086/ERP-091's latency and cost concerns) or just be a bad UX (no feedback if
someone selects 200 files at once).

## Open Questions (need user decision before implementation)

- **What's the cap?** No strong signal either way yet — something like 10 or 20 files per batch
  is a reasonable starting guess, but this is the user's call.
- **Enforced where?** Client-side only (reject/truncate the selection with a message) vs. also
  server-side (reject a batch over the limit at the API level)? Recommend both — client-side for
  immediate feedback, server-side so the limit can't be bypassed by a direct API call.

## Acceptance Criteria

- [ ] Cap value decided
- [ ] Frontend: selecting more than the cap shows a clear message (not a silent truncation) and
      does not start any uploads until the selection is within the cap
- [ ] Backend: the relevant ingestion endpoint(s) reject a batch over the cap with a clear error
- [ ] Test coverage for both the client-side rejection and the server-side rejection

## Notes

Small, well-scoped ticket. No architectural decisions needed beyond the cap number itself.

# ERP-067 — Render SourcePanel Content Properly (No Raw Markdown/HTML)

Status: Backlog
Depends On: ERP-050
Category: Bug — the source panel (ERP-050) shows literal `**`, `#####`, `<mark>`, `<u>` instead
of rendering them

## Description

Live-testing ERP-050 found the source panel renders a chunk's stored text verbatim
(`whitespace-pre-wrap`), so PDF-derived markdown/HTML formatting artifacts show as literal
syntax instead of being rendered. See
`docs/superpowers/specs/2026-09-19-post-erp050-live-feedback-design.md` for the full design
(shared across ERP-067–ERP-074).

## Acceptance Criteria

- [ ] `SourcePanel` renders chunk text through `react-markdown` + `rehype-raw` +
      `rehype-sanitize` (new dependencies, approved) instead of raw `whitespace-pre-wrap` text
- [ ] `<mark>`/`<u>` render as intended (highlight/underline), not stripped or shown literally
- [ ] A disallowed/unexpected tag is sanitized away, not rendered
- [ ] Existing `SourcePanel` tests still pass; new tests cover markdown/HTML rendering and
      sanitization

## Notes

Scoped to `SourcePanel` only — the chat's own `markdownLite.tsx` is unchanged (LLM output is a
small, controlled subset; source content is arbitrary parsed-document output).

# ERP-093 — Self-Service "Delete Account" Button

Status: Done
Depends On: None
Category: Feature

## Description

Live feedback (2026-09-24): there's currently no way for a user to delete their own account —
`DELETE /admin/users/{user_id}` (ERP-040) exists but is admin-only. `app/auth/repository.py`'s
`delete_user_and_owned_data` (ERP-040) already implements the actual FK-safe hard-delete of a
user and everything they own (conversations/messages, documents/chunks, refresh tokens, OIDC
identities, per-owner FAISS index file) — this ticket is mostly about exposing that safely to
the user themselves, not building new deletion logic.

## Decisions (given directly by the user, 2026-09-24)

- **Hard delete**, same irreversible semantics as the existing admin path — no soft-delete/
  grace-period.
- **Confirmation flow**: just one popup warning that deletion is permanent and irreversible —
  no password re-entry, no typed confirmation. Matches `DocumentsPage.tsx`'s existing
  `window.confirm` pattern for bulk document delete.

## Acceptance Criteria

- [x] Decision recorded on the open questions above
- [x] New user-facing endpoint (`DELETE /auth/me`) reusing `delete_user_and_owned_data`,
      requiring the caller's own valid access token (no admin role needed, no `user_id` param —
      always acts on the authenticated caller)
- [x] Frontend: a "Delete account" button (next to "Log out") gated behind a `window.confirm`
      warning
- [x] Tests: successful self-delete (including that owned data is actually cascaded, not just a
      204 status), confirm-decline path, delete-failure path, and structural impossibility of
      targeting another user (the endpoint takes no `user_id` parameter at all)

## Built (2026-09-24)

- `app/auth/service.py`'s `delete_own_account(user_id)` — reuses `delete_user_and_owned_data`
  and `_delete_owner_faiss_index` exactly as `delete_user` does, but (unlike `delete_user`)
  never raises `CannotDeleteSelfError` — deleting your own account is the intended action here,
  not a footgun to block.
- `DELETE /auth/me` in `app/auth/router.py` — takes only `current_user` via the standard
  `get_current_user` dependency, no `user_id` param anywhere, structurally impossible to target
  another account.
- Frontend: a "Delete account" button in `AppShell.tsx`'s nav. Confirms via `window.confirm`
  with wording that data ("documents, conversations, everything") is permanently removed "with
  no way to undo it." A task-review finding was caught and fixed before merge: the initial
  implementation called `logout()` unconditionally even on a failed delete — fixed to check
  `response.ok` first, showing `window.alert` on failure instead of silently logging out a user
  whose account wasn't actually deleted.
- Built via `superpowers:subagent-driven-development` (2 tasks, one fix round, both
  task-reviewed and Approved). Full backend suite (534 passed) and frontend suite (68 passed at
  the time) clean.

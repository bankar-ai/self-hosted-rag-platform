# ERP-084 — Bundled Citation Markers Not Clickable, section_path Shows Raw Markdown

Status: Done
Depends On: None
Category: Bug

## Description

Two pre-existing bugs found live-verifying ERP-080/ERP-076 against production (2026-09-20), on
a real "Safety Guidelines.pdf" document and a real multi-fact question — neither a regression
from the ERP-075 through ERP-083 batch, both gaps that simply hadn't surfaced before:

1. **Bundled citation markers weren't clickable.** The model sometimes cites as `[1, 3, 4]` (one
   bracket, several comma-separated numbers) instead of separate `[1][3][4]` markers.
   `app/generation/service.py`'s `_CITATION_MARKER_RE` has tolerated this bundled form for
   *extracting* which chunks were cited since ERP-065 — but `frontend/src/lib/markdownLite.tsx`'s
   citation-rendering regex only ever matched a single-number `[n]`, so a bundled marker rendered
   as inert plain text instead of clickable pills.
2. **`section_path` showed raw `**bold**`/`<mark>` syntax.** `SourcePanel`'s section-path
   breadcrumb line (`citation.section_path.join(" / ")`) is plain-text, never markdown-rendered
   — unlike the chunk body text, which correctly renders via `ReactMarkdown` (ERP-067). A PDF
   heading the chunker extracted with that decoration already baked into its text (from the
   underlying markdown-export parser) showed the decoration literally instead of being stripped.

## Acceptance Criteria

- [x] A `[1, 3, 4]`-style bundled marker renders as separate clickable pills, one per number,
      each opening the correct citation's source panel
- [x] `citation.section_path` segments have markdown/HTML decoration stripped before display
- [x] Both covered by new tests

## Notes

Frontend-only, no backend change. No new dependency.

## Resolution (2026-09-20)

`markdownLite.tsx`'s `CITATION_MARKER_RE`/`CITATION_MARKER_EXACT_RE` now match
`\[\d+(?:\s*,\s*\d+)*\]` instead of just `\[\d+\]`; `renderTextWithCitations` splits a matched
bundle on `,` and renders each number as its own button (or plain `[n]` if that number has no
corresponding citation), instead of the whole bundle as one block. `SourcePanel.tsx` gained
`stripMarkdownDecoration()` (strips `**` and any HTML-like tags), applied to each `section_path`
segment before joining for display. New tests: a bundled `[1, 2, 4]` marker renders as three
separate clickable elements with the un-cited `[3]` absent; a `section_path` containing
`**bold**`/`<mark>` renders clean. Verified: `tsc`/`oxlint`/`vite build` clean, frontend suite
60 → 62 passing. Merged directly to `main` (PR #55, same reasoning as ERP-083's PR #54 — pure
frontend fix, needed live immediately, not worth a `develop`→`main` round-trip). Live-verified
by the user against production post-deploy.

# ERP-065 — Fix Citation-Marker Parsing for Multi-Number Brackets

Status: Done
Depends On: ERP-055
Category: Bug — ERP-055's citation filter silently drops every citation when the model writes
`[1, 2, 5]` instead of `[1][2][5]`

## Description

Reported live with a concrete reproduction: a real answer contained `[1, 2, 5]` and `[2, 5, 4]`
style citation markers, and the response's `citations` list was empty — no citation list
rendered under the message at all. Root cause confirmed: ERP-055's `_CITATION_MARKER_RE =
re.compile(r"\[(\d+)\]")` only matches a single digit-run inside brackets; `[1, 2, 5]` contains
commas and spaces, so the regex never matches it at all, and `_cited_chunks` returns nothing.

## Acceptance Criteria

- [x] Citation markers are correctly parsed whether the model writes `[1][2][5]` or the
      comma-separated `[1, 2, 5]` form (or a mix of both in the same answer).
- [x] Existing single-marker behavior (`[1]`) and hallucinated-out-of-range-marker tolerance are
      unchanged.
- [x] `SYSTEM_PROMPT` nudges toward the clearer `[1][2]` form going forward, without the parser
      depending on the model actually following that preference.

## Resolution (2026-09-18)

`app/generation/service.py`'s `_CITATION_MARKER_RE` now matches `\[(\d+(?:\s*,\s*\d+)*)\]` (one
or more digit-runs, comma-separated, inside one bracket pair); `_cited_chunks` splits each match
on commas and collects every resulting index, same out-of-range tolerance as before. No change
to `Citation`/response shape — this is a parsing fix, not a contract change.

Verified: ruff/mypy clean, new tests covering `[1, 2, 5]`, mixed `[1][2, 3]` forms, and a
regression test for the original single-marker case; full generation suite passing. Live-tested
against the real local stack with a real multi-fact query, which confirmed `assistant_message_id`
and the citation pipeline work end-to-end -- the model didn't happen to reproduce the exact
comma-bracket form in that run (it wrote a single `[1]` since both facts landed in one chunk), so
the specific `[1, 2, 5]` parsing path is verified by the unit tests above, not a live
reproduction of that exact string.

## Notes

Depends on ERP-055 for the citation-filtering mechanism this regex feeds into.

# ERP-043 — Web UI

Status: Backlog
Depends On: ERP-026

## Description

Everything built so far (ingestion, retrieval, generation, streaming, conversation memory, auth,
admin) is API-only — there is no way to use this platform except via `curl`/Swagger (`/docs`). The
project's next goal is to put a real, usable interface in front of the live deployment so it's
actually demoable/usable as a product, before moving on to the next project (Agentic AI /
LLMOps & Evaluation Platform).

Scope (screens, framework choice, auth-flow UX, how it talks to the streaming endpoint, hosting
alongside the existing FastAPI app vs. separately) is deliberately not decided in this ticket —
that's what the brainstorming/design pass this ticket unblocks is for. This ticket exists so the
work is tracked from the start rather than happening off-the-books.

## Acceptance Criteria

- [ ] To be filled in once scope is decided (brainstorming skill, before any implementation plan)

## Notes

Depends on ERP-026 (auth) since any real UI needs a login flow against the existing
`/auth/*` endpoints. Framework/library choice is subject to this repo's "Research Before
Recommending" rule (`CLAUDE.md`) — current frontend tooling/benchmarks should be checked live
rather than assumed, same discipline already applied to backend library choices (e.g. ADR-006's
reranker choice).

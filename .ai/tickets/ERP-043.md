# ERP-043 — Web UI

Status: Done
Depends On: ERP-026

## Description

Everything built so far (ingestion, retrieval, generation, streaming, conversation memory, auth,
admin) is API-only — there is no way to use this platform except via `curl`/Swagger (`/docs`). The
project's next goal is to put a real, usable interface in front of the live deployment so it's
actually demoable/usable as a product, before moving on to the next project (Agentic AI /
LLMOps & Evaluation Platform).

Scope (screens, framework choice, auth-flow UX, how it talks to the streaming endpoint, hosting
alongside the existing FastAPI app vs. separately) is deliberately not decided in this ticket —
that's what the brainstorming/design pass this ticket unblocks is for. This ticket exists so the
work is tracked from the start rather than happening off-the-books.

## Acceptance Criteria

- [x] A real, usable web frontend exists (React + Vite + TypeScript, deployed to Vercel:
      `https://bankar-ai-self-hosted-rag-platform.vercel.app`, renamed 2026-09-18) covering
      login/register, document upload with
      status polling, and streaming chat with citations.
- [x] Backend confirmed working end-to-end via direct API calls (ingestion, docling fallback,
      generation/chat all `200`).
- [x] Two live-review bugfix rounds completed (PRs #38, #39): SPA-routing 404 on refresh,
      cross-user localStorage leakage, a page that could hang forever on a slow `/auth/me` fetch.
- [x] Final walkthrough through the deployed frontend completed (2026-09-18) — confirmed working
      end-to-end by the user.

## Resolution (2026-09-18)

Closed out after a final live walkthrough of the deployed frontend surfaced four follow-on
observations, tracked as their own tickets rather than reopening this one: ERP-048 (conversation
history didn't survive a fresh login), ERP-049 (no way to delete documents), ERP-050 (visual
design is functional but basic, deferred), plus the three tickets already opened during the
2026-09-17 UI review (ERP-044, ERP-045, ERP-046, still `Backlog`).

## Notes

Depends on ERP-026 (auth) since any real UI needs a login flow against the existing
`/auth/*` endpoints. Framework/library choice is subject to this repo's "Research Before
Recommending" rule (`CLAUDE.md`) — current frontend tooling/benchmarks should be checked live
rather than assumed, same discipline already applied to backend library choices (e.g. ADR-006's
reranker choice).

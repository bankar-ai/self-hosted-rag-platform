# ERP-056 — Surface Retrieval/Reranker Scores as a "Why This Answer" Panel

Status: Done
Depends On: ERP-055
Category: Improvement — the data already exists internally (`RetrievedChunk.score`); it was
just never surfaced past the retrieval layer

## Description

Confirmed in code: `Citation` (`app/generation/schemas.py`) carries no numeric score at all —
`chunk_id`, `document_id`, `section_path`, `page_start`, `page_end`, `source_filename`, nothing
else. The retrieval pipeline already computes a fused RRF score (`app/retrieval/service.py`,
normalized to `(0, 1]`) and, when `rerank=True`, a reranker score (`app/retrieval/reranker.py`)
— this data just dead-ends at the retrieval layer instead of reaching the response.

## Acceptance Criteria

- [x] `Citation` gains a `score: float` field and a `reranked: bool` field indicating whether it
      reflects a fused-RRF score or a reranker score (reuses `RetrievedChunk.score`'s existing
      normalization/semantics unchanged, not a new metric).
- [x] Frontend shows a per-citation "why this was retrieved" affordance displaying the score and
      whether reranking was applied to this answer.
- [x] Scores are only shown for citations that survive ERP-055's "actually referenced" filter —
      built directly on top of ERP-055's change, not a superset.

## Resolution (2026-09-18)

`Citation` (`app/generation/schemas.py`) gained `score: float` and `reranked: bool`;
`_citations_for` (`app/generation/service.py`) now takes a `reranked` flag (the caller's own
`rerank` parameter, passed straight through) and copies `chunk.score` unchanged. Frontend:
`ChatPage.tsx`'s citation list items are now `<details>`/`<summary>` — collapsed by default,
expanding to show "Relevance score: 0.984 (retrieval fusion score)" or "... (reranked)". Kept
deliberately minimal/functional rather than a bespoke panel design, per the ticket's note that
placement/styling likely folds into ERP-050's eventual visual pass rather than needing its own
design effort now.

Live-verified against real Ollama: a real citation response showed `"score": 0.9838...,
"reranked": false` for an unreranked fused-RRF result, and `"reranked": true` when `rerank=True`
was requested (existing test `test_generate_builds_prompt_and_returns_citations` extended to
assert this).

Verified: ruff/mypy clean, `tsc --noEmit`/`oxlint` clean, full backend suite 440 passing (97%
coverage), frontend 24 vitest tests passing. Not deployed to the live VM yet — see this
session's session log.

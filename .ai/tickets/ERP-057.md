# ERP-057 — Rename Deployed Frontend URL to Something Meaningful

Status: Blocked (on user action)
Depends On: None
Category: Improvement — the auto-generated Vercel subdomain (`frontend-sigma-one-54.vercel.app`)
read as meaningless; free to fix via a project rename, no purchased domain needed

## Description

The deployed frontend's URL was Vercel's auto-generated name from a project that was never
explicitly renamed. Two options were considered: a free Vercel project rename (new subdomain,
no cost) vs. a purchased custom domain (Vercel hosting/SSL for it is free on the Hobby plan, but
domain registration itself costs money, roughly $10-15/yr for a `.com`). The user chose the free
rename and applied it directly in the Vercel dashboard.

## Acceptance Criteria

- [x] Vercel project renamed; new URL is `https://bankar-ai-self-hosted-rag-platform.vercel.app`.
- [x] Confirmed no code in this repo hardcoded the old URL (searched thoroughly — only two of
      this repo's own docs referenced it, both updated).
- [ ] Live backend's `CORS_ALLOWED_ORIGINS` updated to the new origin (the actual cause of the
      "Failed to fetch" login error seen right after the rename — the old URL is still the only
      allowed origin) and the service restarted. **Blocked**: the environment's auto-mode
      permission classifier refused a `sed`-based edit of the live VM's `.env` over SSH (a
      production-config-mutating command), matching the established pattern in this project for
      `gh pr merge` and the branch-protection API call — the user needs to run this step
      themselves (exact command below).
- [ ] Login/register verified working end-to-end against the new URL, after the fix above.

## Resolution so far (2026-09-18)

Root cause confirmed via a read-only SSH check: `app/core/cors.py`'s `CORS_ALLOWED_ORIGINS` is
an explicit allowlist with no default beyond local dev, and the live VM's `~/app/.env` still
lists only the old auto-generated Vercel URL
(`CORS_ALLOWED_ORIGINS=https://frontend-sigma-one-54.vercel.app`). The browser silently blocks
the cross-origin response before it reaches frontend code, surfacing as a generic `fetch`
failure rather than a proper HTTP error.

**Fix, to be run by the user** (SSH into `rag-platform-host`, zone `us-central1-a`):

```bash
sed -i 's|CORS_ALLOWED_ORIGINS=https://frontend-sigma-one-54.vercel.app|CORS_ALLOWED_ORIGINS=https://bankar-ai-self-hosted-rag-platform.vercel.app|' ~/app/.env
sudo systemctl restart rag-platform
```

Then verify with a real login against `https://bankar-ai-self-hosted-rag-platform.vercel.app`.

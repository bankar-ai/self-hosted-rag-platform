# ERP-063 — Render Markdown in Chat, Strengthen Answer Structure/Anti-Hallucination

Status: Done
Depends On: None
Category: Bug — the chat UI renders assistant messages as raw text with zero markdown parsing,
so every `**bold**`/bullet the model writes shows up as literal asterisks

## Description

Confirmed live: the model's answers use markdown (`**bold**`, `* bullet`) as instructed, but
`ChatPage.tsx` renders `message.content` as a plain `<p>` with no markdown parsing at all, so
users see literal asterisks instead of formatted text. Separately requested: answers should be
structured (bullet/numbered lists when listing multiple items), complete, and should not
hallucinate or assume beyond the retrieved context.

## Acceptance Criteria

- [x] Assistant messages render real markdown: bold and bulleted/numbered lists, at minimum.
- [x] No new frontend dependency for this — a small hand-rolled renderer for the specific
      subset actually used (bold, bullet lists, numbered lists, paragraphs) instead of pulling
      in a full markdown/remark ecosystem, per this repo's dependency policy (check stdlib/
      existing tools before adding a dependency).
- [x] `SYSTEM_PROMPT` explicitly instructs structured formatting (lists for multiple items) and
      reinforces the existing "use only the provided context" instruction against guessing or
      assuming.

## Resolution (2026-09-18)

Frontend: new `frontend/src/lib/markdownLite.tsx` — a small pure-function renderer covering
`**bold**`, `- `/`* ` bullet lines, `1. ` numbered lines, and paragraph breaks; `ChatPage.tsx`'s
message rendering now calls it instead of dumping raw text into a `<p>`. Deliberately not a
dependency addition (`react-markdown`/`marked` etc.) — the model only ever needs to express this
narrow subset per `SYSTEM_PROMPT`'s own instructions, so a small local renderer covers it exactly
and keeps the bundle unchanged.

Backend: `app/generation/prompt.py`'s `SYSTEM_PROMPT` gained explicit formatting guidance (use
bullet or numbered lists when presenting multiple items, give complete answers) alongside a
reinforced anti-hallucination line (never guess, assume, or state something not directly
supported by the provided context).

Verified: `tsc --noEmit`/`oxlint` clean, 5 new `markdownLite` unit tests (bold, bullet lists,
numbered lists, plain paragraphs, bold-inside-a-bullet), full frontend suite passing; backend
prompt tests updated for the new system prompt text. Not visually click-through-verified in a
real browser this session (no browser tool available) -- covered by the automated renderer
tests and a manual dev-server boot check instead, flagged rather than silently assumed. Not yet
deployed/live-verified against the production environment as of this writing.

## Notes

Scoped to the specific markdown subset the model is instructed to use — not a general-purpose
markdown renderer. If the model's output style changes later (tables, code blocks, etc.), this
renderer would need extending or replacing with a real library at that point, not before.

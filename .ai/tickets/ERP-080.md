# ERP-080 — Citations Survive a Conversation-History Reload

Status: Done
Depends On: None
Category: Bug

## Description

Pre-existing gap, made more costly by ERP-050's clickable-citation feature: citations are only
available for the message that was just streamed/generated in the current session. Reloading a
conversation's history (`GET /conversations/{id}`) returns `content` but not `citations`, so a
reloaded assistant message has no clickable/inline source panel affordance at all.

`ConversationMessageRecord` (`app/generation/models.py`) has no `citations` column today; citations
only ever exist transiently in `GenerationResponse`/the SSE stream and are never persisted.

## Acceptance Criteria

- [ ] `conversation_messages` gains a `citations` column (JSONB, nullable — `None`/absent for user
      messages and pre-migration assistant messages) via a new Alembic migration
- [ ] `generate()` and `generate_stream()` persist the assistant turn's `list[Citation]` alongside
      its `content`, in the same transaction as today's persistence
- [ ] `Message` schema and `GET /conversations/{id}`'s response include `citations`
- [ ] Frontend reads citations from reloaded history the same way it reads them from a live
      response — reloaded assistant messages get working, clickable citation markers

## Notes

Backend schema change + frontend wiring. No new dependency.

## Resolution (2026-09-20, live-verified)

Deployed and confirmed working directly against production, twice: (1) via a scripted API test
(register → ingest → ask a question → check the live response's citations → fetch
`GET /conversations/{id}` → confirm the persisted citation round-trips correctly), and (2) by
the user reloading a real conversation in the browser and confirming citation markers stayed
clickable. No bug found in this ticket's own scope — the single-citation-per-marker case works
exactly as designed. (A related-but-separate frontend gap, bundled `[1, 3, 4]`-style markers
never having been clickable at all, was found during this same live-verification pass and fixed
under ERP-084 — not a citations-persistence bug, a pre-existing marker-rendering gap.)

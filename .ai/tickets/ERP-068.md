# ERP-068 — Copy Affordances (Message, Conversation, Source Panel)

Status: Done
Depends On: ERP-050
Category: Improvement

## Description

No way today to copy an answer, a whole conversation transcript, or a source panel's chunk
text to the clipboard. See
`docs/superpowers/specs/2026-09-19-post-erp050-live-feedback-design.md` for the full design.

## Acceptance Criteria

- [ ] A copy button on each assistant message copies that message's raw text
- [ ] A copy button copies the full current conversation as plain text
- [ ] A copy button in `SourcePanel` copies the loaded chunk's text
- [ ] All three use `navigator.clipboard.writeText` (no new dependency) and show a brief
      confirmation (e.g. icon swap) after copying
- [ ] Tests mock `navigator.clipboard.writeText` and assert the correct text is passed for each

## Notes

None.

## Resolution (2026-09-19)

One shared `CopyButton` component (`getText`/`label`/`className` props, lazy `getText()` at
click time) wired into three places: per-message copy in `ChatPage.tsx` (decoupled from
whether the message has an `id`, unlike the thumbs-up/down feedback which still needs one),
per-conversation transcript copy, and `SourcePanel`'s loaded-state header. No new dependency —
`navigator.clipboard.writeText` only. Verified: `CopyButton.test.tsx` (including a genuine
lazy-evaluation test), `SourcePanel.test.tsx`'s copy test. `ChatPage.tsx`'s two wiring points
have no dedicated test (no test harness for that page, consistent with ERP-050's precedent) —
verified via build/lint plus the underlying component's own tests. Merged to `develop` via
PR #50.

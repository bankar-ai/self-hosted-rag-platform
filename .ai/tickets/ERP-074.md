# ERP-074 — Fix Button Color-Class Cascade Conflict (Invisible Delete/Retry/Dismiss Text)

Status: Backlog
Depends On: None
Category: Bug — confirmed root cause

## Description

Live-verified: the Documents page's Delete/Retry/Dismiss buttons render as empty-looking boxes
with no visible label. Root cause: `components/ui/button.tsx`'s `Button` hardcodes default
`bg-brand`/`text-white` classes, and per-call-site color overrides (e.g.
`bg-white text-red-600`) are appended to the same class string — but Tailwind's utility-class
cascade resolves conflicts by generated-stylesheet order, not by JSX class-string order, so an
override doesn't reliably win. This is a design flaw in `Button`, not new to ERP-050's cosmetic
pass (the same conflict existed with the pre-ERP-050 `bg-slate-900`/`text-white` defaults too).
See `docs/superpowers/specs/2026-09-19-post-erp050-live-feedback-design.md` for the full design.

## Acceptance Criteria

- [ ] `Button` gains a `variant?: "primary" | "outline" | "danger"` prop, default `"primary"`
      (today's look — every existing bare `<Button>` call site needs zero changes)
- [ ] Each variant is a complete, self-contained class set with no shared background/text-color
      utility across variants (so the cascade-order bug cannot recur)
- [ ] `DocumentsPage.tsx`'s Delete → `variant="danger"`; Retry/Dismiss → `variant="outline"`
- [ ] New `button.test.tsx` (none exists today) asserts each variant's rendered class set

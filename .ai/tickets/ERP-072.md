# ERP-072 — Fix Orphaned Temp Files on Dismissed Failed Uploads

Status: Backlog
Depends On: None
Category: Bug — confirmed disk-space leak

## Description

Investigated live: a failed ingestion job's uploaded file is deliberately kept on the VM's disk
(not a bug — it's what lets the existing "Retry" button re-run ingestion without a re-upload).
But dismissing a failed job only clears it from the browser's local list — the backend's
in-memory `JobRecord` and its temp file are never cleaned up, and no automatic cleanup exists
either. On a disk-constrained VM this leaks disk space indefinitely. See
`docs/superpowers/specs/2026-09-19-post-erp050-live-feedback-design.md` for the full design.

## Acceptance Criteria

- [ ] New `DELETE /ingestion/jobs/{job_id}` endpoint (owner-scoped, 404 for unknown/not-owned/
      not-`FAILED`, mirroring `retry_job`'s existing guard)
- [ ] Deletes the in-memory `JobRecord` and unlinks its temp file (and empty parent dir),
      reusing `run_ingestion_job`'s existing cleanup pattern
- [ ] Frontend's "Dismiss" button calls this endpoint (best-effort — a failed call still clears
      local state so the UI doesn't get stuck)
- [ ] New backend tests: happy path, 404 for unknown/cross-owner/non-failed job

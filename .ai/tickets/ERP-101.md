# ERP-101 — Select-All / Deselect-All Control for Chat Document Scoping

Status: Done
Depends On: ERP-044
Category: Improvement

## Description

Found during live dashboard/UX review (2026-09-27). ERP-044 added a checkbox per document in
`Sidebar.tsx` (opt-out model, checked by default) to scope a chat query to a subset of
documents. With more than a handful of documents, there's no way to select or deselect all of
them at once — only one-by-one clicking. `Sidebar.tsx` already tracks
`deselectedDocumentIds: Set<string>` and shows a warning when it equals the full document count
(everything deselected), so the underlying state model already supports this -- there's just no
bulk control wired to it.

## Acceptance Criteria

- [ ] A "Select all" / "Deselect all" control near the document checklist in `Sidebar.tsx`.
- [ ] Toggling it updates `deselectedDocumentIds` the same way individual checkboxes do (no
      parallel/duplicate state).
- [ ] A newly-uploaded document still defaults to selected (opt-out model preserved) regardless
      of any prior bulk action.
- [ ] Test coverage for both directions (select all, deselect all) and the existing
      all-deselected warning still firing correctly after a bulk deselect.

## Notes

Small, contained addition to existing state (`deselectedDocumentIds` in `ChatPage.tsx`, passed
into `Sidebar.tsx`) — no backend change.

## Resolution (2026-09-27)

`ChatPage.tsx` gained `setAllDocumentsSelected(selected: boolean)`, reusing the existing
`deselectedDocumentIds` state (clears it for "select all", fills it with every document id for
"deselect all") — no parallel state. `Sidebar.tsx` gained "Select all"/"Deselect all" text
buttons next to the "Your documents" heading, shown only when there's more than one document.
Verified: frontend 93 passed (was 86), including both directions and the existing
all-deselected warning still firing.

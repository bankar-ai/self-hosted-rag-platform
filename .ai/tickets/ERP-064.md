# ERP-064 — Auto-Scroll Chat to the Latest Message

Status: Done
Depends On: None
Category: Lapse — the message pane never scrolls itself; the design never considered a
conversation long enough to overflow the visible area

## Description

Reported live: once a conversation's messages exceed the visible chat pane height, the view
stays scrolled wherever it was — new messages (including streamed tokens arriving) appear below
the fold with no automatic scroll, requiring a manual scroll to see them.

## Acceptance Criteria

- [x] The chat pane automatically scrolls to show the latest message as new messages arrive.
- [x] Scrolling also keeps pace during token-by-token streaming, not just once a message
      finishes.
- [x] Does not fight a user who has deliberately scrolled up to re-read earlier messages
      mid-stream (best-effort -- not a hard requirement, but avoid being actively annoying).

## Resolution (2026-09-18)

`ChatPage.tsx` gained a bottom-anchor `<div>` ref and a `useEffect` keyed on `messages` (which
already updates on every streamed token via the existing `setMessages` calls in the SSE loop) that
calls `scrollIntoView({behavior: "smooth", block: "end"})` on it.

Verified: `tsc --noEmit`/`oxlint` clean, full frontend suite passing (no dedicated test — this is
a DOM-scroll side effect, not meaningfully unit-testable without a real browser). Not visually
verified in an actual browser this session (no browser tool available) -- the implementation
was code-reviewed against React's `scrollIntoView` behavior and the existing streaming
`setMessages` call sites, but a real click-through to confirm the scroll behavior itself is
still outstanding and should happen on next manual use of the deployed app.

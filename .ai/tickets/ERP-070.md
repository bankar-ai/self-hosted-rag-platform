# ERP-070 — Staged Upload (Explicit "Upload" Step)

Status: Done
Depends On: None
Category: Improvement

## Description

Dropping or selecting PDFs on the Documents page currently uploads immediately. Should instead
stage the files (reviewable, removable) and only upload once the user clicks an explicit
"Upload" button. See `docs/superpowers/specs/2026-09-19-post-erp050-live-feedback-design.md`
for the full design.

## Acceptance Criteria

- [ ] Drag-drop and the file picker stage files (shown with filename + per-file remove) instead
      of uploading immediately
- [ ] Oversized files are still rejected at staging time (unchanged size limit/behavior)
- [ ] An "Upload N files" button uploads everything currently staged
- [ ] Multi-file upload continues to work (already supported end-to-end; confirm no regression)
- [ ] New tests cover: staging doesn't call the upload endpoint; "Upload" triggers it for all
      staged files; per-file removal works

## Notes

None.

## Resolution (2026-09-19)

`DocumentsPage.tsx` gained a `stagedFiles` state: drag-drop and the file picker stage files
(shown with filename + a per-file ✕ remove) instead of uploading immediately; oversized files
are still rejected at staging time. An "Upload N files" button triggers the actual upload for
everything staged. Multi-file support (already present) is unchanged. First test file for this
page (`DocumentsPage.test.tsx`) — a plan-authoring bug in the test setup (a non-decodable
placeholder JWT that would leave the page rendering `null` forever) was caught and fixed by the
implementer during the subagent-driven build, using an existing helper pattern from
`jwt.test.ts`. Merged to `develop` via PR #50.

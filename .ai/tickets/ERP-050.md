# ERP-050 — Visual/UX Redesign (Deferred)

Status: Done
Depends On: ERP-048, ERP-049
Category: Improvement — the current UI is functional but intentionally minimal (plain Tailwind

## Description

Surfaced during the same 2026-09-18 walkthrough as ERP-048/ERP-049: the UI works but looks
basic — flat single-column layouts, no visual hierarchy beyond text size/color, no
document-preview or source-highlighting affordances. Deliberately deferred until ERP-048
(chat history) and ERP-049 (document deletion) — both real functional gaps — shipped first, per
explicit instruction: fix correctness before polish.

Scope is intentionally not decided yet — that's what the brainstorming/design pass this ticket
unblocks is for, same as ERP-043 itself did. The research below is input to that pass, not a
decision.

## Research: current (2026-09-18) visual patterns in notebook-style / RAG chat UIs

Requested explicitly as design inspiration, gathered via live web search per this repo's
"Research Before Recommending" rule (`CLAUDE.md`) rather than relied on from training data.

**Google NotebookLM (2026 interface)** — a three-column layout: Sources (left, manage uploaded
documents), Chat (middle), Studio (right, generated artifacts like study guides/FAQs/outlines).
Its defining pattern is "Source Grounding": every answer carries inline numbered citations, and
clicking one opens a source-preview popover scrolled to the exact passage the answer came from —
this repo already has the citation *data* (`Citation.page_start`/`page_end`/`section_path`) but
the frontend only lists citations as plain text below the answer, not as clickable
popovers/highlights back into a source view.

**Broader 2026 AI-citation UI vocabulary** (Perplexity, Claude, ChatGPT search, Notion AI Q&A,
Granola, per an AYDesign survey of the space): inline numbered superscripts, source preview
popovers, a persistent sidebar source list, evidence highlighting in the underlying document, and
confidence indicators tied to citation strength. All read as extensions of the "traceability"
principle: shorten the visual/interaction distance between a generated claim and the passage
that backs it.

**Open-source self-hosted RAG chat UIs** (for layout/interaction inspiration, not adoption —
this repo builds its own frontend, per ERP-043's "Research Before Recommending" framework
choice): Open WebUI (most widely adopted self-hosted general chat+RAG UI), AnythingLLM
(workspace-based document management, purpose-built around RAG document sets), LibreChat
(multi-provider chat UI). None of the search results surfaced concrete sidebar/source-panel
implementation detail beyond what's summarized above — a closer look would mean reading these
projects' own UI source, not just secondary write-ups, if their specific interaction patterns
become a real candidate during the brainstorming pass.

**Takeaway for the eventual design pass**: the biggest visual/UX gap relative to current-generation
RAG UIs isn't color/typography polish, it's the citation interaction model — a
three-pane-ish layout (sources / chat / detail) and clickable citations that reveal source
context in place, rather than a flat citation list, would likely be the highest-leverage change
if this repo wants to visually read as "current" rather than just "functional."

## Resolution (2026-09-19)

Brainstormed to a scoped design: the ticket's own research already named the real gap
(citation traceability, not color/typography), confirmed live with the user ("basic looks" +
"answer can't be traced back to source"). Design decisions made during brainstorming:

- **No PDF storage/viewer.** Ingestion never persists the original PDF bytes (ERP-053 cleaned
  up what had been a leak) — the source panel shows the already-durably-stored extracted chunk
  text instead, at zero new infrastructure/storage cost.
- **Cited chunk only, no sibling/section expansion** — deliberately simpler for v1; confirmed
  during brainstorming that `get_sibling_chunks` (from ERP-016) is scoped per-document, so
  adding it later wouldn't scale differently even at many uploaded documents.
- **Chunk text fetched on demand**, not embedded in `Citation` — keeps every streamed answer's
  payload lean regardless of citation count.
- **Both citation triggers open the same panel**: the existing citation list below an answer,
  and (new) clickable inline `[n]` markers in the answer text itself.
- **Three-pane layout** (sources+history / chat / source detail), explicitly NOT a NotebookLM
  "Studio" clone — confirmed with the user that layout restructuring has zero infra cost (same
  API calls, different arrangement), and scoped strictly to the source-detail panel, not a new
  generated-artifacts capability.
- **Cosmetic pass**: one deliberate accent color via a Tailwind v4 `@theme` block, replacing
  `index.css`'s previous zero-customization `@import "tailwindcss"`.

Implementation: new owner-scoped `GET /documents/{document_id}/chunks/{chunk_id}` endpoint;
new `SourcePanel`/`Sidebar` frontend components; `markdownLite.tsx` gained clickable citation
markers; `ChatPage.tsx` restructured into the three-pane layout. Built via subagent-driven
development (8 tasks, each independently task-reviewed) plus a final whole-branch review (on
the most capable model) that caught and fixed a real bug before merge: `SourcePanel` had no
stale-response guard, so rapidly switching between citations could silently attribute one
citation's text to a different citation's header (a last-writer-wins race with no error and no
visual tell) — fixed with a `cancelled`-flag guard, verified by a scoped re-review. The same
review also caught that relevance-score/metadata became unreachable whenever the chunk fetch
failed (404/error), even though that data needs no fetch at all — fixed by moving it outside
the fetch-state switch so it always renders once a citation is selected.

**Verified**: backend 502 → 508 tests passing (new coverage: chunk lookup at both repository
and router layers — happy path, unknown chunk, cross-owner access denied), ruff/mypy clean;
frontend 29 → 36 tests passing (`SourcePanel`'s four states including metadata-visible-on-error,
`markdownLite`'s citation-marker parsing), `tsc`/`vite build`/`oxlint` clean. **Live-verified
end-to-end against the production deployment**: uploaded a real document, confirmed the new
chunk-detail endpoint returns correct text/metadata for a real citation from a real generation
answer (including the answer's own inline `[1]` marker), confirmed unknown-chunk and
cross-owner requests both 404, and confirmed deleting the source document makes its chunk
endpoint 404 too (the exact trigger for the panel's "no longer available" state). Deployed via
`git pull` + `systemctl restart` on the VM (no migration — no schema change) and `vercel --prod
--scope bankar-ai` (the scope flag was newly required this session; a bare `vercel --prod`
without it returned "Not authorized" despite `vercel whoami` succeeding). Test users cleaned up
via the admin API. Merged to `develop` via PR #49.

Deferred, not fixed (tracked for a future pass, not blockers): `[n]` markers inside `**bold**`
text aren't clickable (the bold-rendering branch doesn't route through citation-marker
parsing); no responsive handling for the three fixed-width columns on narrow viewports; no
Escape-to-close/focus-management/`aria-label` on inline citation buttons; a conversation
restored from history (after a refresh or switching conversations) has no clickable citations
at all, since restored messages don't carry a `citations` field — this predates this branch but
this feature raises the cost of the gap.

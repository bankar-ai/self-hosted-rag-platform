# ERP-112 — Integrate Langfuse for LLM-Level Observability

Status: Done
Depends On: None
Category: Improvement

## Description

The current observability stack (ERP-028/038/039/042: OpenTelemetry -> Grafana Cloud) covers the
whole app — HTTP/DB/Redis spans, logs, metrics — but has no LLM-specific detail: no token/cost
tracking, no browsable view of individual prompts/contexts/answers, no prompt versioning, and no
UI for the evaluation runs already produced by `app/evaluation/` (ERP-029/030). Langfuse is
purpose-built for exactly that gap and is complementary to, not a replacement for, the existing
OTel+Grafana Cloud setup.

Self-hosting Langfuse is not viable on the live deployment's `e2-micro` VM (official minimums are
2 CPU/4GB RAM per container, or 4 CPU/16GB RAM for a VPS — the whole point of that VM's current
setup, e.g. ERP-037's lazy-docling-import fix, is fitting the app inside ~958MB RAM). Langfuse
Cloud's Hobby tier ($0/month, 50k trace-units/month, 30-day retention, 2 users) is the viable path
and plausibly covers this project's 5-20 sporadic test users indefinitely.

Integration point is `app/generation/client.py`'s `OllamaLLMClient`/`OpenRouterLLMClient`
(`generate`/`generate_stream`), mirroring the existing `get_tracer()`/`get_meter()` wrapping
pattern already in place for OTel.

## Notes

Cost/feasibility research (2026-09-28): self-hosted Langfuse requires ClickHouse + Postgres +
Redis with 2 CPU/4GB RAM per container minimum (or 4 CPU/16GB RAM for VPS) — ruled out for this
project's `e2-micro` deployment. Langfuse Cloud Hobby tier ($0/mo, 50k units/mo) is the
recommended path at this project's traffic scale.

Reusable across the portfolio: a Langfuse Cloud account/project isn't tied to this repo — the same
account can hold separate projects for the future Agentic AI repo (and PEFT/LLMOps), each with
its own free-tier allotment, the same pattern already used for `D:\github-projects\infrastructure-options.md`
(ADR-008). Whether to consolidate under one Langfuse org or create per-project accounts is a
decision for when that repo starts, not now.

Open question deferred to implementation time: whether this ticket's scope includes wrapping
`app/evaluation/` (ERP-029/030) runs too, or is limited to live `/generation/query` traffic only.

# ERP-055 — Citations Should Only List Sources the Answer Actually References

Status: Done
Depends On: None
Category: Bug — the existing design's intent (cite what the answer used) is violated by the
implementation (cites everything stuffed into context, whether used or not)

## Description

Confirmed in code (`app/generation/service.py`'s `_citations_for`): the backend returns a
citation for **every chunk included in the LLM's context window**, not just the chunks the model
actually referenced with `[n]` in its answer text. If 5 chunks were retrieved and included in
the prompt but the model only ever wrote `[1]`, the response still lists all 5 as citations.
This is the concrete cause of the reported "old-fashioned, more citations than necessary" feel
— compare NotebookLM, where an inline `[n]` marker is the only thing that produces a listed
source.

## Acceptance Criteria

- [x] The answer text is parsed for which `[n]` markers actually appear in it.
- [x] Only citations corresponding to markers actually present in the answer are returned —
      applies to both `POST /generation/query` and `POST /generation/query/stream`. Resolved the
      streaming ordering question by restructuring: the SSE `citations` event now fires *after*
      all `token` events, once the full answer text is known, not before.
- [x] An answer that says "I don't have enough information" (the existing `NO_CONTEXT_ANSWER`
      short-circuit) continues to return zero citations, unchanged.
- [x] Existing citation-related tests updated to reflect the new "only if actually cited"
      contract; new tests cover no-citation and hallucinated-out-of-range-marker cases.

## Resolution (2026-09-18)

`app/generation/service.py` gained `_cited_chunks(answer, included_chunks)` (regex `\[(\d+)\]`
over the answer text, 1-indexed against prompt position, silently ignoring an out-of-range
hallucinated marker) and both `generate()`/`generate_stream()` now filter through it before
building citations. The SSE event order changed: `token`* -> `citations` -> `done` (was
`citations` -> `token`* -> `done`) — a genuine behavior/contract change, called out here and in
the commit rather than silently shipped, since citations can now only be known once the full
answer exists.

Bundled with ERP-056 (both touch the same `Citation` construction path): `Citation` also gained
`score`/`reranked` fields in this change (see ERP-056 for detail).

**Live-verified against real Ollama** (not just unit tests with fakes): ingested a document with
two distinct facts, asked a question answerable from only one — the response correctly cited
only that one chunk, not both retrieved/context-included chunks. This is the concrete fix for
the reported "old-fashioned, more citations than necessary" feel, matching NotebookLM's
inline-marker-driven citation model.

Verified: ruff/mypy clean, generation test suite 78 -> 87 tests passing, full backend suite 440
passing, 97% coverage. Not deployed to the live VM yet — see this session's session log.

## Notes

This changed response *content*, not just presentation. Frontend citation list rendering
(`ChatPage.tsx`) needed no structural change for this ticket — it naturally shows fewer items
once the backend stops over-including them (a small display change was made separately, for
ERP-056's score/reranked fields).

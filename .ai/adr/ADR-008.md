# ADR-008 — Cross-Project Infrastructure Options Reference

Status: Accepted
Related Ticket: ERP-037

## Context

While planning how to make this RAG platform reachable ("go live") for a bounded 2-3 month test
window (5-20 users max, then torn down entirely), the hosting/infra research kept surfacing options
relevant to more than just this one repository — the same "cheap, temporary, easy to tear down"
constraint applies to the future Agentic AI, PEFT/LoRA, and LLMOps repositories named in
`docs/architecture.md`. Re-deriving this research separately in each future repo would be wasted
effort, and infra decisions made in isolation per-repo risk drifting inconsistently (e.g. picking a
different "temporary Postgres" provider three times for no reason).

## Decision

Maintain a single shared reference document, `D:\github-projects\infrastructure-options.md`, at the
root of all portfolio projects (siblings of this repo), covering hosting/compute/database/GPU/LLM-API
options evaluated specifically against the "live 2-3 months, then gone" constraint shared by every
project in this portfolio. Each future repo should reference this same file rather than duplicating
or re-deriving its own version.

The document tracks each option with a `Status` of either `Deployable now` (verified enough to use
today) or `Needs exploration` (a real candidate not yet verified against actual resource needs).

## Alternatives Considered

- **A per-repo infra doc in each project**: rejected — duplicates research, risks inconsistent
  decisions across sibling projects solving the same underlying constraint (temporary, cheap,
  low-traffic hosting).
- **No written record, decide ad hoc each time**: rejected — this is exactly the kind of "look at
  this again and again" the user explicitly wanted to avoid; the research (Render vs GCP vs Azure vs
  AWS vs Modal vs RunPod vs Kaggle vs Colab vs OpenRouter vs Langfuse, etc.) is expensive to redo and
  time-sensitive (pricing/free-tier terms shift; the doc records a research date for this reason).

## Consequences

- This repo's own hosting decision (GCP Always Free e2-micro, pending live verification; Render
  Starter as fallback) is recorded in the shared doc, not duplicated here in full — this repo's own
  docs should link to it rather than re-explain it.
- The shared doc lives outside this repo's git history (it's at the `D:\github-projects\` root, a
  sibling directory, not inside `self-hosted-rag-platform/`), so it is **not version-controlled by
  this repo's git** and has no CI/review gate of its own. Future repos that also reference it should
  be aware edits are unreviewed and untracked by any single repo's history.
- The document's per-provider pricing/limits will go stale as providers change terms; it carries an
  explicit research date and a re-verify-before-committing-spend note for this reason. It is not a
  substitute for live-testing an option before actually depending on it (see ERP-037's open items).
